## 📝 Documentation Standards

### When to Update Documentation

**Always update docs when:**
- Adding a new feature
- Changing API endpoints
- Modifying setup process
- Fixing common issues
- Changing dependencies
- Updating environment variables

**Which files to update:**
- New feature → Update `FEATURES.md`, `CHANGELOG.md`, `README.md`
- API change → Update `API_DOCUMENTATION.md`, `CHANGELOG.md`
- Setup change → Update `TEAM_SETUP.md`, `RUN_WITHOUT_DOCKER.md`
- Bug fix → Update `CHANGELOG.md`, troubleshooting sections

### Documentation Checklist

Before submitting PR with docs:
- [ ] Updated relevant markdown files
- [ ] Added to CHANGELOG.md
- [ ] Verified all links work
- [ ] Checked formatting (preview in VS Code)
- [ ] Updated code examples if needed
- [ ] Added to QUICK_REFERENCE.md if common task
